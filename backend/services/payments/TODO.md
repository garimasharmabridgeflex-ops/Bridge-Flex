# functions-payments — Architecture & Implementation Notes

This service is isolated from `core` and `communication`, and is the only place
that talks to Stripe.

## Architecture note (October 2026 specification)

**Stripe Connect Express is NOT used.**
KFlex operates as an employer / agency paying practitioners directly through
**internal UK PAYE payroll** (supported via CSV exports for HMRC Basic PAYE
Tools in Phase 8). Practitioners are never paid out via Stripe Connect transfers.

Instead, this service is responsible for:

1. **Nursery subscriptions** — £199/mo Standard, £299/mo Premium and a £9.99
   one-off Pay As You Go booking fee, collected through Stripe-hosted Checkout.
2. **Membership lifecycle** — activation, renewal, failed payment, plan changes
   and cancellation, driven by Stripe webhooks.
3. **Billing self-service** — Stripe's hosted billing portal for card updates,
   receipts and cancellation.

Nursery staffing invoices (weekly charges from approved timesheet hours) are
still generated by core and settle by card or BACS outside this service; an
invoice carrying a `stripeInvoiceId` is marked paid automatically when Stripe
reports that invoice paid.

## Functions

| Entry point | Trigger | Notes |
| --- | --- | --- |
| `CreateSubscriptionCheckout` | HTTP, authenticated | Creates/reuses a Stripe customer, then either a Checkout Session or an in-place price change on an existing subscription. |
| `CreateBillingPortalSession` | HTTP, authenticated | Requires a stored `stripeCustomerId`. |
| `StripeWebhook` | HTTP, unauthenticated | Verified with `STRIPE_WEBHOOK_SECRET` (`t=…,v1=…` HMAC-SHA256 over `timestamp.payload`). Idempotent via `stripeEvents/{eventId}`. |
| `CreatePayout` | HTTP | Legacy placeholder, returns `501 PAYMENTS_NOT_YET_BUILT`. |

## Where state lands

`subscriptions/{nurseryId}` gains `stripeCustomerId`, `stripeSubscriptionId`,
`stripePriceId`, `lastPaymentAt`, `lastPaymentPence`, plus the existing
`status` / `planId` / `currentPeriodStart` / `currentPeriodEnd` /
`cancelAtPeriodEnd` fields the rest of the app already reads. Notifications are
written to `notifications/{id}` so the nursery sees payment events instantly
through its Firestore listener.

## Configuration

All five values come from Secret Manager at deploy time (see `deploy.sh`):
`stripe-secret-key`, `stripe-webhook-secret`, `stripe-price-standard`,
`stripe-price-premium`, `stripe-price-payg`. `APP_PUBLIC_URL` (a plain env var)
sets where Stripe returns the browser — `public/billing/checkout-return.html` on
Firebase Hosting.

## Deliberate boundaries

- No card numbers, CVCs or bank details ever reach KFlex code or Firestore;
  payment surfaces are Stripe-hosted only.
- No Stripe Go SDK: every call is a plain form-encoded REST request, and the
  signature check is implemented in `function/stripe.go`, keeping the module's
  dependency set to functions-framework + Firestore/Firebase.
- Cancellation of a card subscription happens in Stripe (portal or webhook);
  core's `CancelSubscription` refuses with `USE_BILLING_PORTAL` for those rows
  rather than flipping local flags while the card keeps being charged.
